# 场景三：决策测算

用户在做决定前想算清楚：发券或降价划不划算、毛利还剩多少、该补多少货。命令前缀都是 `python <SKILL>/scripts/run.py`。

**原则：只算账，不预测销量。** 不说「发券后能多卖多少」，只给「销量至少要涨多少才不亏」（保本销量增幅），让用户自己判断能不能做到。

## 价格类方案测算（优惠券、降价、赠品）

```bash
python <SKILL>/scripts/run.py simulate --product <商品> --coupon 15
python <SKILL>/scripts/run.py simulate --product <商品> --new-price 149
python <SKILL>/scripts/run.py simulate --product <商品> --coupon 10 --gift-cost 6
```

- `--coupon`：券面额（元），按每件抵扣计算；`--new-price`：新到手价（元），两者二选一；`--gift-cost`：赠品每件的成本（元）。按订单抵扣的券、满减券，要说明测算是按每件抵扣算的，实际每件让利会更小。
- 数据里没有到手价或成本价时，输出会提示缺什么。请用户提供后加上 `--price-now 当前到手价`、`--cost 成本价`。

**怎么解读结果：**

| 字段 | 含义 |
| --- | --- |
| `estimate.price_before` / `price_after` | 调整前后的到手价 |
| `estimate.margin_rate_before` / `margin_rate_after` | 调整前后的毛利率（已扣赠品成本） |
| `estimate.breakeven_lift` | 保本销量增幅：销量至少涨这么多，总毛利才不降 |
| `gap_after` | 调整后比竞品贵（正）或便宜（负）多少；没有竞品价时为空 |
| `checks` | 毛利底线、调价权限、最低价保护三项检查 |
| `ok` | false 表示低于毛利底线，**这个方案不能用**（此时其他检查不再计算）；true 只代表毛利过线，调价权限、最低价保护是否通过要看 `checks` |

**回答怎么写：**

1. 结论先行，格式如：「给 X 元券后到手价 X 元，毛利率从 X% 降到 X%，销量至少要涨 X% 才能保住总毛利。」
2. 逐条说明三项检查。没通过的要说后果：低于最低价会「破价，可能影响后续大促价格」，超出调价权限会「需要上级审批」。
3. `ok` 为 false 时，明确说不能用，并用更小的券面额再算一次，给出一个能通过的选项。

**用户问「发多少券合适」**：取 3～4 档（例如 5、10、15、20 元），每档各算一次，用一张表对比到手价、毛利率、保本销量增幅和检查结果。用户关心「最多能发多少」时，在过线和不过线的两档之间再试一两档，给出守住毛利底线的最大面额。说明各档的取舍，不要替用户判断销量能涨多少。

**先看下滑原因再测算**：用户想用发券、降价「拉销量」时，先用 `query` 看这个商品近期是访客少了还是转化低了。如果原因明显不是价格（例如评分下滑、断货），在测算之外提醒一句「价格可能不是主因」，并建议先做单品诊断。

**用户问「该怎么办」而不是指定方案**：先按 `analyze.md` 做单品诊断，方案从诊断结果的动作库里选，再用本节测算细节。

## 库存与补货

```bash
python <SKILL>/scripts/run.py stock
python <SKILL>/scripts/run.py stock --products <商品>
```

- 每个规格的状态分三种：断货、偏低（可售天数低于补货周期）、充足。按紧急程度排序。
- `suggest_qty` 是建议补货量，`rule` 里有计算公式：日均销量 ×（补货周期 + 安全库存天数）− 当前库存 − 在途量。断货的规格按断货前的正常日均销量计算。
- 有 `in_transit` 的写上在途数量和到货日期。已有在途、不用追加的，也要说明。
- 回答用一张表：商品 · 规格、状态、当前库存、可售天数、建议补货量。结尾写上用到的补货周期和安全库存天数，并提示「规则不同可以告诉我」。
- 数据里没有库存时，直接说明做不了。

## 经营规则

测算用到的规则（毛利底线、调价权限、最低价保护天数、补货周期、安全库存天数）都有默认值，`simulate` 输出的 `rules` 和 `stock` 输出里能看到当前取值。**第一次做测算时，要在回答里说明用了哪些规则。** 用户说出自己公司的规则后，执行：

```bash
python <SKILL>/scripts/run.py settings --set 毛利底线=30% 调价权限=15% 补货周期=10
```

然后重新测算。不要修改 Skill 里的任何配置文件。
